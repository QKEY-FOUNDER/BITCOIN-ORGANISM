# DATA_POLICY.md
## BITCOIN-ORGANISM — Data Boundary & Custody Policy

---

## Purpose

This document defines the **non-negotiable boundary** between what is considered **organism DNA** and what is considered **metabolic data** within the BITCOIN-ORGANISM project.

This policy exists to preserve:

- Integrity  
- Reproducibility  
- Long-term sustainability  
- Artistic and scientific clarity  

The repository is not a data dump.  
It is a genome.

---

## Core Principle

**What is versioned is DNA.  
What is generated is metabolism.**

Metabolism is transient.  
DNA is eternal.

---

## Versioned DNA (Tracked in Git)

The following elements are considered **canonical DNA** and are always versioned:

- Source code (engine, state, immune, geo, memory, output layers)
- Canonical models and contracts
- Manifests and protocols
- Documentation (README, MANIFESTO, DATA_POLICY, ARTISTIC protocols)
- Deterministic pipelines and schemas
- Symbolic and semantic definitions of state

These elements define **how the organism thinks, reacts, and expresses itself**.

They must be:

- Reviewable  
- Auditable  
- Reproducible  
- Immutable in history  

---

## Metabolic Data (Never Versioned)

The following elements are **explicitly excluded** from Git versioning:

- Daily or monthly OHLCV CSV files
- BTC dominance time series
- Geo-derived datasets
- Normalized or merged datasets
- Logs, reports, runtime outputs
- Daily snapshots and heartbeat artifacts
- Regenerated sound frames and intermediate outputs

These elements are:

- Regenerable  
- Time-dependent  
- Environment-dependent  

They represent **metabolism**, not structure.

Their exclusion is intentional and permanent.

---

## Reproducibility Clause

All excluded data **must be reproducible** from the versioned DNA using:

- Deterministic pipelines
- Public or documented data sources
- Explicit transformation logic

If a dataset cannot be regenerated from DNA, it does not belong to this organism.

---

## Artistic Output Exception

Final artistic outputs (sound, music, performance artifacts):

- Are **not versioned** in Git
- May be published externally (albums, archives, exhibitions)
- Must reference the generating state via:
  - Date
  - Regime
  - Hash or symbolic signature

Art is expression.  
Git is memory.

They must not be confused.

---

## External Mirrors

Historical imports, mirrors, or large archives:

- Are kept **outside** the versioned repository
- May be referenced symbolically or by hash
- Are never treated as canonical truth

The organism does not hoard history.  
It learns from it.

---

## Non-Negotiable Rule

**No daily data enters the versioned repository.  
No exception.  
No justification.  
No retroactive inclusion.**

Violating this rule breaks the organism.

---

## Governance

This policy applies to:

- Maintainers
- Contributors
- Artists
- Researchers
- Automated agents

Any contribution that violates this boundary will be rejected.

---

## Closing Statement

This policy is not about storage.  
It is about meaning.

The organism remains light.  
Its memory remains clean.  
Its evolution remains infinite.
